Fixes

  • Google Sign-In routing fix on macOS 27 (Something went wrong / Bluetooth Passkey error). Neutralized PublicKeyCredential.getClientCapabilities() and removed unentitled WebAuthn constructors (PublicKeyCredential, AuthenticatorResponse, AuthenticatorAssertionResponse, AuthenticatorAttestationResponse) in unentitled WKWebView builds while keeping CredentialsContainer intact for macOS Keychain Password AutoFill. Entering your email on accounts.google.com now routes directly to the Password / Google Prompt / 2FA screen instead of failing on /v3/signin/challenge/pk.
  • Restored ad-hoc TCC compatibility (flags=0x2(adhoc)). Removed --options runtime during ad-hoc DMG re-signing while preserving LiteGemini.entitlements so macOS tccd does not restrict SafariPlatformSupport.Helper AutoFill or microphone capture.

Notes

  • Because macOS restricts third-party WKWebView Passkey assertions to Apple-entitled web browsers, sign in once using Keychain Password AutoFill (Touch ID), your Google password, or Try another way → Google Prompt; your session persists across launches and updates.
  • The app is not notarized, so macOS blocks it on first launch. Open System Settings → Privacy & Security and click Open Anyway, or run: 
    xattr -dr com.apple.quarantine "/Applications/Lite Gemini.app"
